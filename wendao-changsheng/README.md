# 《问道长生》项目总览

> 这是《问道长生》项目的入口文档，写给接手或参与这个项目的人和 AI 会话。
> 先读完这一页，再按「阅读顺序」去读具体文档。

## 1. 这是什么游戏

| 项目 | 内容 |
|---|---|
| 名称 | 《问道长生》 |
| 类型 | 文字修仙 Roguelite |
| 平台 | **TapTap H5 小游戏**，手机竖屏优先 |
| 单局时长 | 10–20 分钟 |
| 一句话 | 每局随机一段修仙人生：选出身、抽天赋、领一个宿命，在有限寿元内修炼、探索、结缘、斗法、突破，最后迎来一个结局；经历写进「因果录」，解锁下一局的新内容 |

## 5. 已经做出的关键决定

以下决定已经和项目负责人确认过。**修改前请先和负责人商量**，不要自行推翻。

| # | 决定 | 详见 |
|---|---|---|
| 1 | **没有回合制战斗。** 冲突用「斗法」解决：玩家只选一次应对方式，按大胜、险胜、落败、惨败四档一次结算，用一段文字描述过程 | content-expansion 0.5 |
| 2 | **斗法文字不用通用模板。** 每场斗法都有专属文字，由「起、交锋、结果、余韵」四个片段随机拼接，另有条件变体、变数和会记仇的有名号对手 | combat-texts 第一节 |
| 3 | **玩家可以选性别（男 / 女）。** 不影响数值；称呼用 `{性别:男性文本|女性文本}` 写法；道侣按异性配对（考虑国内审核） | systems 第 18 节 |
| 4 | **因果录 = 条件解锁 + 因果点。** 因果点只用于「提前了悟」和每局最多 2 个「前缘」，不直接加属性 | systems 第 8 节 |
| 5 | **周期、持续时间、收入一律按「行动次数」或「境界」计算，不按年数。** 境界越高，一次行动跨的年数越多（炼气 1 年，大乘 150 年），按年计算会失控。年龄条件（如「百岁前结丹」）例外 | systems 1.7 |
| 6 | **物品卖价以物品表为准。** 事件里只写「获得某物品」 | content-expansion 0.2、systems 第 3 节 |
| 7 | **单局时长靠「境界越高，行动越耗时」来控制。** 每个大境界约 25–35 次决策 | systems 1.2–1.4 |
| 8 | **首版不做联网。** 每日天命只保留「每日同一种子」，排行榜以后再做 | systems 第 7 节 |
| 9 | **技术方案：纯网页。** TypeScript 加轻量界面框架，传记卡用 Canvas 绘制；不用 Godot 等游戏引擎（导出包太大） | — |
| 10 | **素材全部使用 CC0 授权**，来自 `game-assets/superpowers/`，只挑用得到的，压缩后控制在几 MB | game-assets/README.md |

## 6. 写作与修改约定

改文档或写新内容时，请遵守：

- **玩家一律用「你」称呼。** 需要按性别区分时，用 `{性别:师兄|师姐}` 这种写法；能用中性称呼（道友、前辈、阁下）就不用性别称呼。
- **数值记号**：「修为 +X%」指当前小层级的百分比；「灵石 +N×」指乘以当前境界的灵石系数；事件里写的耗时都是炼气期的数值，实际要乘以时间系数。
- **新增周期性内容时**，遵守 systems 1.7 的规则表。
- **每个选项都要有实际结果**（原方案开发原则第 1 条），写清收益、代价或风险。
- **斗法文字**：每个片段都要是完整的句子，并且能和同一场斗法的任意其他片段接上；新的斗法照 combat-texts 第一节的结构来写。
- **改了一处，检查它在其他文档里的引用。** 四份文档之间互相引用很多（例如 NPC 线引用事件编号、事件引用物品表）。
- **不要在仓库里写入任何 AI 模型的名称。**

## 9. TapTap 上架相关

- **云开发环境**：已安装 TapTap 官方命令行工具 `@taptap/cli`（命令 `taptap-cli`），但网络策略拦截了 `developer.taptap.cn` 和 `api.tapapis.cn`，连不上，也没有登录。
- **负责人自己的电脑**：`taptap-cli` 已经由负责人本人授权登录，可以直接建游戏、上传 H5 包、填写商店资料。负责人的另外两款 H5 小游戏就是从这台电脑上架的，上架、上传、提审都在那里做。
- 从工具自带的官方文档中确认的信息：
  - 上架资质共 8 类：游戏版号、ICP 备案、隐私合规、防沉迷、AI 内容声明、软件著作权、IP 授权书、安全评估。
  - **不是都必须交**。TapTap 会根据 5 项事实自动判断哪些必须：是否联网、有无内购、有无 AI 内容、有无 IP 授权、是否「文字剧情模拟」类。
  - **没有版号也能上架，但只能「开放试玩」；正式上线才需要版号。**
- 负责人另外两款 H5 小游戏的实际经验：
  - 按「含 AI 内容、不联网、无内购、无 IP 授权」申报后，服务器判定的必交资质为空，提审后正常上线。
  - H5 小游戏的激励视频广告走开发者中心「广告变现」开通，**不需要软著**；广告位 ID 由 TapTap 官方的小游戏开发工具按游戏查询。所以第 8.3 节「要不要变现」只是产品选择，没有资质上的障碍。
- 本游戏首版的情况：不联网、无内购、无 IP 授权、很可能属于「文字剧情模拟」。**设计文档和文字内容由 AI 协助撰写，很可能需要按「含 AI 内容」申报。** 最终哪些资质必须交，以登录后 TapTap 服务器的判断为准。
